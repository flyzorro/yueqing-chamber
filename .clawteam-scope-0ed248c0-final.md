## Source Request
Build an independent company directory module for Yueqing Chamber mobile app: add a distinct 企业名单/company directory entry, create a dedicated company list page separate from member-page semantics, reuse existing company data/API if already available, keep scope UI-first and fail closed if backend/schema changes are not strictly proven necessary. Acceptance: distinct entry and independent page exist, basic company info renders correctly, members/activities/services do not regress, company-directory-focused validation and typecheck pass.

## Scoped Brief
在现有 mobile app 中交付一个最小 UI 闭环：新增独立的企业名单入口与独立企业列表页，复用已存在的企业接口与移动端 API 配置，不主动触达后端/schema/db；以基础企业信息渲染、现有 members/activities/services 不回归、以及移动端 company-directory-focused 验证和 typecheck 通过为验收目标。

## Unknowns
- distinct entry 的最小落点是否要求首页入口、底部 Tabs，或两者都要
- basic company info 的最小字段集合未被显式限定，需要以现有接口真实返回为准
- company-directory-focused validation 的最终命令需在 Setup 阶段根据仓库现状确认

## Leader Assumptions
- 现有 /api/companies 已可复用，因此本轮执行形态先按 ui-only 处理
- 独立企业列表页应为独立路由/页面文件，而不是 members 页面换文案
- 如果现有接口字段不足，则本轮应收窄展示，而不是主动扩 backend/schema

## Out of Scope
- backend/api/schema/db/auth/crawler 层新增或重构
- 企业详情页和高级筛选/收藏/排序等扩展功能
- dashboard/web 端同步改造
- 超出防回归所需范围的 members/activities/services 功能修改

## Risks/Blockers
- 入口导航层级定义不够明确，可能引发验收口径差异
- 企业接口真实字段若与预期不一致，UI 只能按现有字段 fail closed
- 需要在 Setup 阶段确认真实可运行的验证命令，避免误报验证完成

## Recommended Next Step
Setup followed by explicit post-scope materialization through the workflow/state machine; do not create downstream tasks ad hoc.
