## 一、核心实现模式

### 1.1 数据模型命名规范

**规则**：使用 `snake_case` 与现有模型保持一致

```prisma
// ✅ 正确：与 Activity、Member 等模型一致
model Information {
  createdat    DateTime @default(now)
  updatedat    DateTime @default(now)
  publisherid  String
}

// ❌ 错误：不要用 camelCase
model Information {
  createdAt    DateTime @default(now)  // 不一致
}
```

### 1.2 API 错误响应格式

**统一格式**：
```typescript
interface ErrorResponse {
  success: false;
  error: string;
  code?: 'INFO_NOT_FOUND' | 'UNAUTHORIZED_DELETE' | 'INVALID_INPUT';
}
```

**错误码表**：
| HTTP | Code | 触发场景 |
|------|------|----------|
| 400 | `INVALID_INPUT` | 标题/内容为空、分类无效 |
| 401 | - | 未登录或 Token 无效 |
| 403 | `UNAUTHORIZED_DELETE` | 非管理员且非发布者删除 |
| 404 | `INFO_NOT_FOUND` | ID 不存在 |
| 500 | `SERVER_ERROR` | 服务器内部错误 |

### 1.3 权限检查中间件

```typescript
// 删除权限：管理员 OR 发布者本人
export async function authorizeInfoDelete(req, res, next) {
  const info = await informationStore.getById(req.params.id);
  const isAdmin = process.env.ADMIN_PHONES?.includes(req.user.phone);
  const isOwner = info.publisherId === req.user.id;
  
  if (!isAdmin && !isOwner) {
    res.status(403).json({ success: false, error: '无删除权限' });
    return;
  }
  next();
}
```

## 二、Expo Router 导航陷阱

### 2.1 router.back() 前提条件

**陷阱**：`router.back()` 需要导航历史存在，否则会报错 "GO_BACK was not handled"

**解决方案**：在 `_layout.tsx` 中注册路线

```typescript
// ❌ 错误：没有注册，router.back() 会失败
<Stack>
  <Stack.Screen name="(tabs)" />
</Stack>

// ✅ 正确：注册后才有导航历史
<Stack>
  <Stack.Screen name="(tabs)" />
  <Stack.Screen name="information" options={{ headerShown: false }} />
  <Stack.Screen name="create-information" options={{ headerShown: false }} />
</Stack>
```

### 2.2 发布后刷新列表

**陷阱**：`router.back()` 返回已挂载页面，useEffect 不会重新执行

```typescript
// ❌ 错误：列表不会刷新
Alert.alert('成功', '发布成功', [
  { text: '确定', onPress: () => router.back() },
]);

// ✅ 正确：强制重新加载页面
Alert.alert('成功', '发布成功', [
  { text: '确定', onPress: () => router.replace('/information') },
]);
```

### 2.3 登录状态检查位置

```typescript
// ✅ 正确：在 useEffect 中异步检查
const [isLoggedIn, setIsLoggedIn] = useState(false);

useEffect(() => {
  const checkLogin = async () => {
    const token = await AsyncStorage.getItem('token');
    setIsLoggedIn(!!token);
  };
  checkLogin();
}, []);

// 渲染时根据状态显示不同 UI
{isLoggedIn && <Pressable onPress={() => router.push('/create')}>发布</Pressable>}
```

## 三、无障碍规范（iOS）

### 3.1 触摸区域最小尺寸

**规则**：≥ 44x44px（iOS 人机界面指南）

```typescript
// ✅ 正确：hitSlop 扩大触摸区域
<Pressable
  style={styles.backButton}  // padding: 4
  hitSlop={{ top: 10, bottom: 10, left: 10, right: 10 }}
  accessibilityRole="button"
  accessibilityLabel="返回上一页"
  accessibilityHint="返回到上一个页面"
>
  <Text>‹ 返回</Text>
</Pressable>
```

### 3.2 无障碍属性

| 属性 | 用途 | 示例 |
|------|------|------|
| `accessibilityRole` | 元素类型 | `"button"` |
| `accessibilityLabel` | 简短描述 | `"返回上一页"` |

## 五、常见问题 FAQ

### Q1: "GO_BACK was not handled" 错误

**原因**：路线未在 Stack layout 中注册

**解决**：
```typescript
// mobile/app/_layout.tsx
<Stack.Screen name="information" options={{ headerShown: false }} />
```

### Q2: 发布后列表不刷新

**原因**：页面已挂载，useEffect 不执行

**解决**：使用 `router.replace()` 而非 `router.back()`

### Q3: Token 在本地有效但远程无效

**原因**：JWT_SECRET 环境变量不一致

**解决**：检查 Railway Dashboard 中的环境变量配置
