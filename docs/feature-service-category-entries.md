# Feature Plan — 公共服务分类入口补齐

## Goal
在现有“公共服务”页面上，补齐需求中缺失的服务分类入口，并统一分类命名与展示顺序。

## Why this first
这个 feature 适合作为当前项目的第一批真实任务，因为它具备：
- 改动范围小
- 依赖少
- 不要求新增复杂后端能力
- 不涉及登录权限、数据库迁移、Prisma 可用性等高风险链路
- 验收清晰，适合快速验证真实开发流程

## Scope
本次只做“分类入口展示补齐”，不做后续业务流转。

### Required categories
需要补齐并展示的分类：
- 法律服务
- 金融服务
- 财税服务
- 工商服务
- IT 技术
- 政务服务
- HR 服务
- 产品服务
- 信息发布

### Required adjustments
- 统一分类名称
- 统一分类展示顺序
- 统一入口卡片/图标/文案风格（在现有页面风格内最小调整）

## Out of scope
本次明确不做：
- 预约/申请/咨询流转
- 后台配置能力
- 分类排序后台化
- 详情页/表单页
- 新增复杂 API
- 新增数据库表或迁移

## Acceptance criteria
完成后应满足：
1. 公共服务页包含本次约定的全部分类入口。
2. 分类名称与需求口径一致。
3. 页面结构清晰，入口展示风格一致。
4. 不影响已有页面和已有公共服务入口能力。
5. 项目 typecheck 通过。
6. 与该页面相关的现有测试/最小验证通过。

## Suggested branch
- `feature/service-category-entries`

## Suggested implementation notes
建议优先沿用现有公共服务页面的数据结构和渲染方式，尽量避免为了这次需求引入新的配置层或抽象层。

优先顺序建议：
1. 找到现有公共服务页面与分类常量来源
2. 补齐缺失分类
3. 统一命名/排序
4. 本地验证页面展示
5. 跑 typecheck / 最小测试

## QA checklist
最小验证建议：
- 公共服务页能看到新增分类入口
- 页面无明显布局错乱
- 已有分类未消失
- 点击入口后如果当前产品定义是占位/静态入口，则行为保持一致
- Web 端基础访问正常

## Notes
这是一个“低风险、易验收”的起步 feature，目标不是一次把公共服务做深，而是先把信息架构补齐。后续如果要做预约、咨询或后台配置，应拆成独立 feature。
